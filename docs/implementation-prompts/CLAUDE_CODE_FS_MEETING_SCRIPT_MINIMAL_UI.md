# Claude Code追加修正指示｜FS商談画面 スクリプト中央領域の簡略化

## 0. 対象

```text
/Users/maekawahiroyuki/hd-system-auto
```

今回の対象は **FS商談実行画面の中央「トークスクリプト」領域** です。

右側の商談メモ統合UI、商談資料、DB、Obsidian、AI解析、トークスクリプト本文は変更しないでください。

---

# 1. 目的

現在の商談画面中央には、読み上げスクリプト以外の情報が多く表示されており、
実際の商談中に「今読むべき文章」が見づらくなっています。

商談中画面の優先順位を以下へ変更してください。

```text
1. 読み上げスクリプト
2. フェーズ名
3. フェーズの目的
4. 前へ / アウト / 次へ の最低限操作
5. その他の補助情報
```

補助情報は今回の商談実行画面では原則非表示にします。

---

# 2. フェーズタイトルを小さくする

現在のような大きな表示:

```text
PHASE ⑦

制作事例の紹介
```

を縮小してください。

完成イメージ:

```text
⑦ 制作事例の紹介
制作事例を見せ、品質への率直な評価を得る
```

フェーズ番号・タイトル・目的を、スクリプト本文の上にコンパクトに表示します。

推奨:

```css
.meeting-phase-header {
  padding: 10px 0 14px;
}

.meeting-phase-number {
  font-size: 10px;
}

.meeting-phase-title {
  margin: 0;
  font-size: clamp(20px, 2vw, 26px);
  line-height: 1.35;
}

.meeting-phase-purpose {
  margin-top: 4px;
  font-size: 12px;
  line-height: 1.5;
  color: var(--muted);
}
```

現在の40px級の巨大タイトルは商談実行画面では使用しないでください。

---

# 3. 「このフェーズの目的」カードを廃止

現在のような独立した大きなカード:

```text
このフェーズの目的

制作事例を見せ、品質への率直な評価を得る
```

は商談実行画面では表示しないでください。

目的はフェーズタイトル直下に1行または2行で小さく表示します。

データ自体は削除しません。

---

# 4. 中央領域は「基本スクリプト」を主役にする

タイトル・目的の直下にすぐ読み上げスクリプトを表示してください。

完成順:

```text
⑦ 制作事例の紹介
制作事例を見せ、品質への率直な評価を得る

────────────────────

基本スクリプト

こちらも、今回と同じように店舗様へ...
...
```

「基本スクリプト」のラベル自体も小さくして構いません。

推奨:

```css
.script-section-label {
  font-size: 12px;
  font-weight: 700;
}
```

本文:

```css
.document-script {
  font-size: 16px;
  line-height: 1.8;
  max-height: none;
  overflow: visible;
}
```

中央カラム全体をスクロールさせ、スクリプト本文の内側で二重スクロールさせないでください。

---

# 5. 商談中画面から非表示にする項目

以下は **今回の商談実行画面では表示不要** です。

機能・データ自体を削除せず、UIから非表示にしてください。

```text
HPの役割
例：Instagramを見たお客様が迷わず予約できる公式情報

商談メモ
ヒアリング回答や重要事項を記録
```

右側に統合した「商談メモ」があるため、中央側の商談メモ入力UIは表示しません。

---

# 6. 「確認事項」を商談実行画面から非表示

現在表示されている以下のような確認事項UIは、今回すべて商談実行画面から外してください。

例:

```text
確認事項

参考サイトへの第一印象
回答メモ
相手の回答を短く記録
詳細を残す（必要な時だけ）

品質・デザインへの感想
回答メモ
相手の回答を短く記録
詳細を残す（必要な時だけ）

自店でも作りたいか
回答メモ
相手の回答を短く記録
詳細を残す（必要な時だけ）
```

要件:

- 表示しない
- 入力必須にしない
- 「次へ」の条件としてUI入力を要求しない
- DB上の既存回答データは削除しない
- 過去データの互換性を維持
- スクリプトテンプレ管理画面では確認事項を残してよい

つまり:

```text
テンプレート定義として確認事項は保持
商談実行画面では非表示
```

としてください。

---

# 7. 「次へ進む条件」を商談実行画面から非表示

現在の:

```text
次へ進む条件
品質への評価を確認したら取材へ
```

も商談中には表示不要です。

商談実行画面では非表示にしてください。

ただしテンプレートデータとしては保持してください。

既存ロジックで厳格なgateが設定されている場合は、
今回のUI簡略化に合わせて「確認事項入力がないと次へ進めない」状態にはしないでください。

トークスクリプト本文を読んだ担当者が任意のタイミングで次へ進めるようにします。

---

# 8. 「使用禁止表現」を商談実行画面から非表示

現在の:

```text
使用禁止表現
必ず同じ品質になります
```

は商談実行画面では表示しません。

データ定義・管理画面には残してください。

将来、AIがリアルタイムで禁止表現を検知する用途へ利用できるため、削除は禁止です。

---

# 9. 「戻る場所を選択」を削除

現在の中央下部にある:

```text
戻る場所を選択
⑦ 制作事例の紹介

← 前のステップ
選択した場所へ戻る
アウトが来た
次へ進む →
```

という複雑なナビゲーションを簡略化してください。

商談中の基本操作は以下だけにします。

```text
[← 前へ]      [アウト]      [次へ →]
```

または:

```text
← 前へ        アウト        次へ →
```

「戻る場所を選択」のselectは通常画面から削除してください。

任意のフェーズへ移動したい場合は、
左側のフェーズ一覧を直接クリックして移動できるため、
中央側に戻り先selectを重複表示する必要はありません。

---

# 10. アウトボタン

「アウトが来た」は残して構いません。

ただし表示は短く:

```text
[アウト]
```

または:

```text
[アウト返し]
```

としてください。

押した時に既存のアウト返し候補を表示する機能は維持します。

右側の「アウト返し候補」折りたたみと連動させても構いません。

# 11. ナビゲーション位置

中央スクリプトの最下部または画面下部に、コンパクトな操作バーとして配置してください。

推奨:

```text
┌───────────────────────────────┐
│ ← 前へ       アウト      次へ → │
└───────────────────────────────┘
```

要件:

- スクリプト本文に重ならない
- 画面幅が狭くても折り返さない
- 3つのボタンだけ
- 「次へ」を最も目立たせる
- 左フェーズ一覧から任意移動可能
