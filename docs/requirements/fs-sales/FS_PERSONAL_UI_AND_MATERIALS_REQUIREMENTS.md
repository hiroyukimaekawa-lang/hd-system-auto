# HD AIアシスタント｜FS個人画面 UI改修要件書

## 1. 改修目的
現在のFS画面を、商談担当者が迷わず使える実務導線へ整理する。

今回の目的は以下。
- サイドバーをFS業務の順番に並べ替える
- 商談準備で入力した店舗情報を商談画面上部へ自動表示する
- 現在のトークスクリプト本文は変更しない
- 商談画面右側に常時入力できる殴り書きメモ欄を配置する
- 店舗情報・スクリプト・メモを同じ画面で同時に確認できるようにする

## 2. 今回変更するもの
- サイドバーの項目名と順番
- FS画面のページ構成
- 商談画面上部の店舗情報ヘッダー
- 商談画面右側のメモ欄
- 商談準備情報と商談画面の連携
- メモの自動保存・復元

## 3. 今回変更しないもの
- 現在の商談トークスクリプト本文
- 現在の商談フェーズ構成
- 必須確認項目
- 既存の商談開始・中断・再開・終了処理
- 既存の進捗管理FMT
- 既存のアウト返し内容
- 既存のObsidian保存処理

## 4. サイドバー改修

### 4.1 新しい表示順
1. トークスクリプトテンプレ
2. 商談準備
3. 各種案件用
4. 各種案件結果と振り返り

### 4.2 各メニューの役割

#### トークスクリプトテンプレ
- 現在登録されているトークスクリプトを確認する画面
- スクリプト本文は現状維持
- 一般FS担当者は閲覧中心
- 編集機能がある場合は管理者のみ

#### 商談準備
- 商談前情報を登録する画面
- IS引き継ぎ情報を貼り付け・整理する
- 保存後、「各種案件用」に案件を追加する

#### 各種案件用
- 商談前・商談中・中断・次回対応待ちの進行中案件一覧
- 案件を選択して商談開始・再開・案件情報確認を行う

#### 各種案件結果と振り返り
- 商談終了済み案件の一覧
- 商談結果、メモ、ヨミ、獲得商材、次回アクション、振り返りを確認する

### 4.3 既存メニューの統合先
| 現在の項目 | 統合先 |
|---|---|
| ホーム | 各種案件用の上部サマリーへ統合 |
| 商談支援 | 各種案件用 |
| 商談準備 | 商談準備 |
| トークスクリプト | トークスクリプトテンプレ |
| 商談履歴 | 各種案件結果と振り返り |
| 業務自動化 | 今回のFS個人画面では非表示 |
| HD AI | 今回のFS個人画面では非表示または別導線 |
| 設定 | 右上ユーザーメニューまたは管理者画面へ移動 |

### 4.4 サイドバー表示仕様
- 現在の配色と基本デザインは維持
- 選択中メニューは背景色と左側アクセント線を表示
- サイドバーは左固定
- 狭い画面では折りたたみ可能
- アイコンは各項目に合うものへ変更

## 9. 右側の殴り書きメモ

### 9.1 配置
- 商談画面右側に常時表示
- スクリプトとは独立スクロール
- 幅は380〜440pxを目安
- 13インチ画面でも使用できること

### 9.2 入力欄
- 大きめのテキストエリア
- 商談開始直後から入力可能
- プレースホルダー:
  `相手の発言、反応、懸念、言質などを殴り書きしてください`

### 9.3 推奨入力方式
- Enter：メモ追加
- Shift + Enter：改行
- 日本語変換確定中のEnterでは追加しない
- `event.isComposing` を考慮する
- 追加後は入力欄を空にして次のメモをすぐ入力できる

### 9.4 保存仕様
- 3〜5秒ごとに自動保存
- フォーカスが外れた時に保存
- フェーズ移動時に保存
- 商談中断・終了時に保存
- 再読み込み後に復元
- 商談再開後に復元

### 9.5 推奨データ形式
```json
{
  "memoId": "memo_xxx",
  "meetingId": "meeting_xxx",
  "phaseId": "phase_05",
  "content": "HP自体は作りたいが、電気は奥様確認が必要",
  "createdAt": "2026-08-04T12:50:00+09:00"
}
```

### 9.6 将来拡張
将来以下を追加できる構造にする。
- AI解析
- 温度感
- HP制作意思
- 言質
- 懸念
- 次に聞く質問
- アウト返し候補

今回のMVPでは、メモ入力・保存・復元を最優先とし、AI解析は必須にしない。

## 13. データ連携要件

商談準備データを商談画面へ自動反映する。

```json
{
  "storeName": "店舗名",
  "ownerName": "オーナー名",
  "websiteUrl": "公式HP",
  "instagramUrl": "Instagram",
  "googleMapsUrl": "Googleマップ",
  "otherLinks": [],
  "isNotes": "IS時点の備考",
  "isPerson": "IS担当者",
  "meetingAt": "商談日時",
  "products": []
}
```

- 商談画面で二重入力させない
- 商談準備を更新したら商談画面へ反映
- 過去商談には当時の情報スナップショットを残すことを推奨

## 14. API要件

### 案件取得
`GET /api/fs/deals/:dealId`

返却:
- 店舗情報
- 商談準備情報
- リンク
- IS備考
- 現在の商談セッション
- 商談メモ

### 商談メモ追加
`POST /api/fs/meetings/:meetingId/memos`

```json
{
  "phaseId": "phase_05",
  "content": "相手の発言"
}
```

### 商談メモ一覧
`GET /api/fs/meetings/:meetingId/memos`

## 15. セキュリティ要件
- 店舗名、オーナー名、IS備考、メモを `innerHTML` で直接挿入しない
- 原則 `textContent` を使用
- URLは `http:` または `https:` のみ許可
- 外部リンクは `noopener noreferrer`
- メモAPIでは対象商談IDを検証
- 他案件のメモを誤更新しない

# 追加要件：FS商談資料ライブラリ・フェーズ連動リンク

## 20. 追加改修の目的

FS担当者が商談中に必要な資料を探すため、Google Drive、Google Slides、Google Sheets、Google Docs、外部サイトを行き来している。

今回、HD AIアシスタントのFS画面内に「商談資料ライブラリ」を追加し、次を実現する。

- トーク中に使う資料を、現在の商談フェーズに応じてすぐ開ける
- エネパル、AMEX、三井住友ビジネスオーナーズ、ACマスターカードの申込資料を整理する
- 申込書テンプレートとアフィリエイトリンク管理表へすぐアクセスできる
- 資料の追加・差し替え・停止を、ソースコード変更なしで行える
- 右側の殴り書きメモ欄を圧迫しない
- 将来的に会社共通DBへ移行できるデータ構造にする

現在のトークスクリプト本文・フェーズ構成は変更しない。

```text
[トークスクリプト] [商談資料ライブラリ]
```

商談資料ライブラリでは、全資料の閲覧・検索・追加・編集・停止を行う。

### 22.3 商談画面

店舗情報ヘッダーの直下に、コンパクトな資料バーを配置する。

```text
┌────────────────────────────────────────────────────┐
│ 店舗情報ヘッダー                                    │
├────────────────────────────────────────────────────┤
│ このフェーズで使う資料                              │
│ [ご提案資料] [料金表] [関東エリア] [全資料を見る]    │
├───────────────────────────┬────────────────────────┤
│ トークスクリプト           │ 殴り書きメモ             │
└───────────────────────────┴────────────────────────┘
```

右側は殴り書きメモ専用として維持する。資料一覧を右側へ縦積みしない。

### 22.4 全資料を見る

「全資料を見る」を押すと、中央モーダルを開く。

- 右側メモ欄を恒久的に隠さない
- モーダルを閉じると、商談中の入力位置・フェーズ・メモを維持する
- 資料は新しいタブで開く
- 現在のHD AIアシスタント画面を別URLへ遷移させない

## 24. 現在フェーズとの連動

各資料に `phaseTags` を持たせ、現在フェーズに合う資料を最大4件まで資料バーへ表示する。

トークスクリプトの本文やフェーズ構成は変更せず、既存フェーズIDへタグを紐づける。

### 24.1 推奨マッピング

| フェーズの意味 | 表示資料 |
|---|---|
| 会社紹介・HP説明 | 新規事業ご提案資料 |
| 制作事例・HP必要性 | 新規事業ご提案資料 |
| 無料化の仕組み | 新規事業ご提案資料、エネパル公式サイト |
| 電気説明・明細確認 | パルパワー料金表、関東エリア確認ページ |
| 申込書読み合わせ | 申込書テンプレート |
| AMEX提案・申込 | AMEX申込フロー、アフィリエイトリンク管理表 |
| 三井住友提案・申込 | 三井住友カード発行マニュアル、アフィリエイトリンク管理表 |
| AC提案・申込 | ACマスター申込方法、アフィリエイトリンク管理表 |

### 24.2 案件商材による絞り込み

商談準備で対象商材が選択されている場合、その商材に関係する資料を優先する。

例：

- AMEX対象外の案件では、AMEX申込資料を資料バーへ自動表示しない
- 電気対象案件では、エネパル資料を優先する
- 「全資料を見る」では権限の範囲内ですべて確認可能

## 29. アフィリエイトリンクの扱い

## 30. API要件

### 資料一覧

```http
GET /api/fs/materials
```

クエリ例：

```text
?category=electricity&product=enepal&active=true
```

### 現在フェーズ用資料

```http
GET /api/fs/meetings/:meetingId/materials?phaseId=:phaseId
```

処理：

1. 商談の対象商材を取得
2. 現在フェーズを取得
3. 権限を確認
4. `phaseTags` と商材が一致する資料を抽出
5. `sortOrder` 順で最大4件を返す

### 資料追加

```http
POST /api/fs/materials
```

### 資料更新

```http
PUT /api/fs/materials/:materialId
```

### 資料停止

```http
PATCH /api/fs/materials/:materialId/status
```

### 初期データ取込

```http
POST /api/fs/materials/import
```

またはCLI：

```bash
npm run fs:materials:import -- --file=config/private/fs-sales-materials.local.json
```

## 31. URL検証・セキュリティ

- `https:` を原則必須とする
- `javascript:`、`data:`、`file:` を拒否する
- 外部リンクは新しいタブで開く
- `target="_blank"`
- `rel="noopener noreferrer"`
- URL・タイトル・説明を `innerHTML` へ直接入れない
- 表示は `textContent` を使用する
- 不正URLは保存時に400エラーとする
- 資料IDはユーザー入力値をそのままファイルパスへ利用しない
- Google Driveの閲覧権限エラー時は「アクセス権限を確認してください」と表示する

## 32. エラー時の表示

- URL未登録：`リンク未登録`
- 非公開・権限不足：一覧へ表示しない
- Driveアクセス不可：`Google Driveの閲覧権限がありません`
- 外部サイト停止：`資料を開けませんでした`
- 取得失敗でも商談画面・メモ保存・スクリプト表示は継続する

資料機能の障害で商談画面全体を停止させない。
